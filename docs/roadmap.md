# 物纪 · Chronicle — 交付路线

采用可运行的垂直版本逐步交付。每个里程碑均应能通过 Docker Compose 启动，并使用真实数据验证，不积累只能在最后集成的孤立模块。

## Milestone 1 — 核心账本

状态：✅ 已实现首个可运行版本，并通过 PostgreSQL 集成测试与 Docker 冒烟测试。

目标：完成单用户登录与第一件物品的完整生命周期录入。

范围：

- TypeScript monorepo 与基础 CI
- PostgreSQL、Drizzle schema 与迁移
- 首次初始化向导
- 单管理员登录、会话和 CLI 密码重置
- 应用设置：名称、基础币种、时区
- 默认分类与标签
- 创建、查看、编辑、回收资产
- 取得方式与已知/未知成本
- 生命周期状态事件
- 基础资金事件
- 持有天数、服役天数和净日均成本领域计算
- 响应式应用外壳、资产列表、创建页和详情时间线

验收：

1. 全新数据库首次访问只能进入初始化流程。
2. 初始化后未登录不能访问任何资产或附件接口。
3. 可创建购买、受赠和未知成本资产。
4. 状态从使用中切换到退役再恢复后，服役天数正确分段累计。
5. 卖出回款可使生命周期净成本为零或负数。
6. 金额计算无浮点误差；同日取得和处置按 1 天计算。
7. 关键公式具备单元测试，核心 API 具备集成测试。

## Milestone 2 — Dashboard 与完整资产体验

状态：✅ 已实现，并通过领域单元测试、PostgreSQL API 集成测试、响应式浏览器检查与生产构建验证。

目标：让用户能够日常浏览、筛选并理解个人资产组合。

范围：

- 卡片/表格双视图
- 搜索、分类、标签、状态、日期和金额筛选
- 完整详情指标
- 当前总体日均成本
- 净投入、期间支出、物品数量与状态统计
- 成本趋势与事件注释
- 分类构成、闲置率和最近活动
- 成色与结构化缺陷历史
- 借出与归还历史
- 维修事件（保修到期提醒归入 Milestone 3 的通用提醒）
- 浅色、深色和跟随系统主题
- 像素点缀与“岁痕”视觉语言

验收：

1. 当前 Dashboard 排除退役和已处置资产。
2. 历史趋势仍能显示资产在过去实际参与组合的区间。
3. 成本未知资产不被当作零成本，并显示统计完整度。
4. 手机可完成创建、搜索、状态切换和主要详情浏览。
5. 借出与维修使用成对工作流维护状态，不能通过通用状态接口制造无对应记录的“借出中”或“维修中”。

## Milestone 3 — 附件、订单与提醒

状态：✅ 已实现，并通过 PostgreSQL API 集成测试、Worker 任务测试、响应式浏览器检查与生产构建验证。

目标：补齐真实购买记录、售后资料和主动提醒。

范围：

- ✅ 封面、相册和附件
- ✅ 私有文件访问、文件类型验证与缩略图
- ✅ 可选订单及跨商品优惠分摊
- ✅ 附加成本可通过 `accessory` / `upgrade` 资金事件记入主机；独立配件一律作为单独物品（关系管理界面已撤下）
- ✅ 通用一次性/周期提醒
- ✅ 多提前量、确认、稍后提醒和有限重复
- ✅ PostgreSQL-backed Worker 与任务管理
- ✅ Telegram Provider
- ✅ 通用 Webhook Provider
- ✅ 通知测试、发送日志、幂等与失败重试

验收：

1. ✅ 未登录无法通过猜测 URL 访问附件。
2. ✅ 订单各物品分摊金额精确回收到订单总额。
3. ✅ Worker 重启不会重复发送已成功通知。
4. ✅ 一个渠道失败不阻塞其他渠道。
5. ✅ 借出归还与保修到期可直接创建提醒。

## Milestone 4 — 种草、多币种、导出与个人 API

状态：✅ 已实现，并通过 PostgreSQL API 集成测试、导入导出校验、个人令牌 Scope 隔离与 OpenAPI 文档端点验证。

目标：覆盖购买决策、外币资产和数据可迁移性。

范围：

- ✅ 种草清单与多个平台链接
- ✅ 封面图片、备注、目标价、预算、优先级与计划日期
- ✅ 手工价格快照与曲线
- ✅ 购买后一键转资产，并保留价格历史
- ✅ 多币种物品、资金事件、订单与种草转入
- ✅ Frankfurter v2 历史汇率 Provider、最近前一有效日回退与手工覆盖
- ✅ 版本化 ZIP 完整导出：JSON、CSV、附件、校验清单
- ✅ 完整导入、格式校验与冲突预览（replace 覆盖）
- ✅ 默认关闭、带 Scope 的个人访问令牌（Bearer `ct_…`，创建时只显示一次）
- ✅ OpenAPI 稳定文档端点：`/api/docs` 与 `/api/v1/openapi.json`

验收：

1. ✅ 历史交易汇率锁定，最新汇率变化不重写旧账。
2. ✅ Frankfurter 故障不阻止以手工汇率入账。
3. ✅ 导出后能在全新实例恢复等价核心数据和附件。
4. ✅ 只授予 `wishlist:write` 的 Token 不能读取附件或修改资产。

## Milestone 5 — AI 估值建议（已移出当前产品范围）

状态：已取消用户可见功能。

AI 估值建议、外部检索、周期估值任务、采用快照和预测折旧不再属于当前产品范围，也不会出现在 Dashboard、物品详情或用户操作流程中。旧版本数据库表、API 契约和 Portable Export/Import 字段暂时保留，只用于兼容已有实例和历史归档，不再继续扩展。

## Phase 2 — 订阅、数字许可与微信通知

状态：✅ 已完成。订阅/数字许可独立账本、完整状态与价格工作流、共享标签/资料/提醒、数据迁移和六种通知渠道均已落地。

范围：

- ✅ 周期订阅与一次性数字许可的独立领域模型
- ✅ 预计扣款与实际扣款账本
- ✅ 免费试用、优惠期、涨价、失败扣款、取消与续费的完整工作流 UI
- ✅ 月/年预计支出与实际支出
- ✅ 域名、证书和维护期限与提醒引擎的一键关联
- ✅ 企业微信群机器人
- ✅ Server酱第三方微信推送 Provider
- ✅ PushPlus 第三方微信推送 Provider
- ✅ Bark iOS 推送 Provider（支持官方与自托管服务）

明确不保存账号密码或 License Key。

## 已取消需求

- 不再规划购物平台自动价格追踪或采集。
- 不建设 `PriceCollector`、商城 API 适配、浏览器采价扩展、自动目标价监控或采集器健康系统。
- 种草清单仅保留公开商品链接、目标价和用户主动录入的手工价格快照；它们是个人研究资料，不是自动追价能力。

## 实现审计结论

截至当前版本，审计中列出的 P0/P1/P2 功能均已实现：

- ✅ Export/Import v1 对旧版本估值记录保持兼容，同时覆盖订阅、价格历史、扣款、订阅标签和订阅附件。
- ✅ 回收站列表、恢复、强确认永久删除及 Worker 到期清理。
- ✅ 自定义分类与固定计算语义状态。
- ✅ 序列号、购买渠道、订单号、保修/延保资料及快捷提醒。
- ✅ 受审计事件更正和维修外币汇率锁定；AI 估值汇总已从用户界面移除。
- ✅ 通知渠道测试发送、简体中文优先的 i18n 基础设施。
- ✅ 订阅试用、优惠、涨价、失败扣款、取消/续费、共享标签/附件/提醒。
- ✅ 企业微信、Server酱、PushPlus 通知渠道。
