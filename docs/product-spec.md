# 物纪 · Chronicle — 产品规格

> 记录每一件拥有的时间与价值。

状态：已确认，可进入实现
技术项目名：`thingcost`（品牌展示名为“物纪 · Chronicle”）

## 1. 产品定位

物纪是一个面向个人的、自托管的物品生命周期与成本管理服务。它帮助用户记录耐用物品从取得、使用、闲置、借出、维修、退役到处置的完整过程，并用一致、可追溯的口径展示持有成本、服役成本和价值变化。

产品不是家庭 ERP、日常记账软件、密码管理器、证券投资工具或消耗品库存系统。

### 1.1 目标用户与部署边界

- 单用户；不开放注册，不做家庭共享或多租户。
- 主要运行在个人服务器、NAS 或小主机上。
- 通过局域网、Tailscale 或其他 VPN 访问。
- 默认仍启用单管理员登录。
- 支持桌面与手机浏览器；首版不做 PWA、离线同步或原生 App。

## 2. 设计原则

1. **真实现金流与预测价值分离**：AI 估值不能修改真实购入成本、支出或处置回款。
2. **关键事实可追溯**：资金、状态、成色、估值和关键日期通过事件保留历史。
3. **录入负担渐进**：只要求最少字段，详细资料按需补充。
4. **计算口径透明**：每个指标可解释，未知值不能伪装成零。
5. **核心功能本地可用**：外部服务不可用时，资产管理与统计仍正常工作。
6. **自托管数据可迁移**：提供完整、版本化的便携导出。

## 3. 实物资产范围

首版只管理耐用品；每条资产记录代表一个可独立拥有生命周期的具体物品。

### 3.1 取得方式

- 购买
- 受赠
- 继承
- 自制
- 交换
- 未知

“成本为零”与“成本未知”必须严格区分。成本未知的资产仍计入物品数量、状态与估值统计，但不参与需要成本的聚合指标，并影响数据完整度提示。

### 3.2 渐进式录入

必填字段：

- 名称
- 主分类
- 取得日期
- 取得方式
- 实际现金成本（仅在已知或适用时）

可选字段：

- 品牌、型号
- 原价、优惠、运费、税费
- 成色与缺陷
- 购买渠道、订单号
- 保修与售后信息
- 序列号（仅作为普通敏感资料，不发送给 AI）
- 封面、相册、发票、订单截图、说明书等附件
- 备注
- 标签

### 3.3 分类与标签

- 提供默认主分类模板。
- 用户可增删改自定义分类。
- 每件物品只能有一个主分类，避免聚合成本重复。
- 每件物品可有多个标签，用于交叉筛选。
- 首版不做复杂的多级分类树。

### 3.4 订单与优惠分摊

- 快速模式：直接为单件物品录入实付成本。
- 订单模式：一个订单包含多件物品，共享总优惠、运费或其他调整。
- 默认可按商品原价比例分摊，也允许手工调整。
- 分摊结果必须精确回收到订单总额，舍入差额应可解释。
- 每件物品最终拥有明确的取得成本。

### 3.5 配件与升级

充电头等能够独立持有的配件统一作为独立资产管理，不提供“属于”或“搭配”等关系管理能力。若某项费用不需要独立生命周期，可将其记为主物品的一笔配件或升级支出。

## 4. 生命周期模型

### 4.1 默认状态

- 使用中
- 闲置
- 借出
- 维修中
- 退役
- 已卖出
- 已赠送
- 已丢弃
- 已遗失
- 已退货

用户可增加自定义显示状态，但每个状态必须映射到固定语义：

- 是否累计服役天数
- 是否仍持有
- 是否为终止处置

默认情况下，使用中、闲置、借出和维修中均累计服役天数；退役停止服役计时但仍累计持有天数；卖出、赠送、丢弃、遗失和退货结束持有。

### 4.2 状态时间线

每次状态变更记录：

- 旧状态与新状态
- 生效日期/时间
- 备注
- 关联业务信息（例如借用人、预计归还日、维修事件）

退役可恢复为使用中或其他服役状态；服役天数只累计各段服役区间。处置状态为业务终态，但录入错误可通过受审计的更正操作修复。

### 4.3 持有与服役天数

- **持有天数**：取得日至处置日或当前日期。
- **服役天数**：累计所有被标记为“计入服役”的自然日区间。
- 按应用时区的自然日计算，取得当天为第 1 天。
- 当天取得并处置也按 1 天计算。
- 用户不能直接修改天数，只能修正日期或状态事件。

## 5. 资金与成本模型

所有金额使用货币最小单位的整数保存，不使用浮点数。

### 5.1 资金事件

至少包括：

- 购入/取得现金支出
- 优惠、退款
- 运费、税费、交易手续费
- 维修
- 升级
- 配件
- 处置费用
- 卖出回款
- 其他关联支出或收入

每笔后续支出均带有“是否计入生命周期净成本”标记。

默认计入：维修、不可分离升级、交易手续费、处置费用。
默认不计入：电费、燃料、耗材等日常运营费用。

### 5.2 核心公式

```text
生命周期净成本
= 取得现金成本
+ 所有计入成本的后续支出
- 退款
- 卖出净回款
```

```text
购入日均成本 = 取得现金成本 / 服役天数
生命周期净日均成本 = 生命周期净成本 / 服役天数
持有日均成本 = 生命周期净成本 / 持有天数
```

若净成本为负，界面改用“净收益”和“日均净收益”表达，不显示含糊的负成本文案。

### 5.3 当前组合总体日均成本

```text
当前总体日均成本
= Σ（当前仍在服役且未处置资产的生命周期净日均成本）
```

- 退役资产不进入当前组合主指标。
- 已处置资产不进入当前组合，但保留在生命周期归档和历史趋势中。
- 历史趋势按当时状态和当时已发生资金事件重建。
- 趋势变化应标记购入、维修、退款、卖出等原因。

## 6. 成色、保修、维修与借出

### 6.1 成色

- 固定等级：全新、近新、良好、一般、较差。
- 可记录划痕、维修、缺件、功能异常等结构化缺陷与自由备注。
- 成色变化进入时间线，不能无痕覆盖历史。

### 6.2 保修与维修

- 保存保修来源、起止日期、延保信息和附件。
- 维修事件记录故障、费用、送修日期、取回日期和备注。
- 保修到期与取回日期可接入通用提醒。
- 首版不做发票 OCR 或自动解析保修规则。

### 6.3 借出

- 记录借用人自由文本、借出日期、预计归还日和备注。
- 归还后保留借用历史。
- 催还提醒只发送给管理员，不自动联系借用人。
- 不建立联系人数据库。

## 7. Dashboard 与资产界面

### 7.1 Dashboard 首屏

视觉主指标：当前总体日均成本。

辅助指标：

- 当前净投入
- 期间日均支出
- 当前 AI 估值（与现金成本明确分区）
- 当前物品数量
- 分类成本构成
- 日均成本趋势
- 闲置率、借出与维修数量
- 即将到期的提醒
- 最近活动

首版使用固定布局，不做拖拽、缩放或面板编辑器。

### 7.2 资产列表与详情

- 默认卡片视图，可切换高密度表格视图。
- 手机默认卡片；桌面记住用户选择。
- 共享搜索、分类、标签、状态、金额区间和日期筛选。
- 列表只展示少量关键数字；详情页分组展示完整指标。

完整指标包括：原价、优惠额与优惠率、购入成本、后续支出、处置回款、净成本、持有与服役天数、两类日均成本、闲置率、维修次数与费用、回收率、AI 估值、保值率及年化贬值率。

## 8. 附件与删除

- 支持封面、相册和普通附件。
- 附件保存在私有挂载目录，数据库保存元数据。
- 使用随机存储名，禁止 Web 服务器直接暴露目录。
- 附件只通过经过授权的应用接口访问。
- 首版不做应用层附件加密，部署文档建议宿主机磁盘加密。

删除进入回收站，默认保留 30 天。处置、归档与删除是不同概念。永久删除需要强确认并清理附件。

## 9. 种草清单

第一阶段支持：

- 名称、分类、图片与备注
- 多个平台链接
- 手工当前价格、目标价格与价格快照
- 预算、优先级、计划购买日期
- 手工价格曲线
- 购买后一键转为正式资产，并保留价格历史

不再规划购物平台自动价格追踪或采集。种草清单只保存用户主动添加的公开链接、目标价与手工价格快照；不建设商城 API 适配、爬虫、浏览器采价扩展或自动目标价监控。

## 10. 通用提醒

提醒支持：

- 一次性与周期规则
- 多个提前量（如 30、7、1 天）
- 普通通知与待确认任务
- 确认、忽略、稍后提醒
- 有上限的重复发送与失败重试
- 全局默认渠道，单条提醒可覆盖
- 发送历史、去重与失败日志

支持渠道：Telegram、通用 Webhook、企业微信群机器人、Server酱、PushPlus。

提醒采用应用全局时区，默认 `Asia/Shanghai`。纯日期与精确时间分别建模。

## 11. 多币种

- 默认基础币种为 CNY。
- 每笔交易保存原币金额、币种、换算汇率、来源和参考日期。
- Frankfurter v2 为默认参考汇率 Provider，Base URL 可配置。
- 自动填充交易日期的参考汇率，用户可改为账单实际汇率。
- 周末或节假日可回退到最近有效日期，并明确标记。
- 交易确认后锁定历史汇率，不能被未来最新汇率重写。

## 12. AI 估值

### 12.1 流程

1. 使用品牌、型号、取得时间、地区、成色和缺陷构建检索请求。
2. Tavily 搜索公开的新价、二手挂牌或可获得的成交证据。
3. 兼容模型清洗异常样本并生成结构化报告。
4. 输出估值区间、中位值、置信度、证据来源、估值日期和未来分段预测。
5. 用户确认后才生成采用的估值快照。

### 12.2 Provider

- 内置 DeepSeek 配置预设，不写死模型版本。
- 支持 OpenAI-compatible Chat Completions。
- 支持 OpenAI Responses API。
- Provider 声明自身结构化输出、工具调用等能力。
- 所有输出转换为统一内部 Schema 并校验。

### 12.3 权限与隐私

- AI 只生成建议，不能直接覆盖账本或估值。
- 默认手动触发，可按资产启用月度、季度或年度估值。
- 支持调用预算、并发限制和结果缓存。
- 只发送必要文本，不发送序列号、发票、附件、借用人或私人备注。
- 运行前展示即将发送的数据摘要。
- AI 估值与现金成本在 Dashboard 中严格分开。

### 12.4 折旧表达

- 保存每次估值快照，而不是永久绑定单一折旧率。
- 根据历史快照推导观察到的年化贬值率。
- AI 可提供未来 1、2、3 年分段预测区间。
- 已观察数据与预测数据使用不同视觉语义。

## 13. 第二阶段：订阅与数字许可

虚拟资产采用独立领域模型，不伪装成实物资产。

范围：

- 周期订阅、云服务、服务器、域名等
- 买断软件、永久会员等一次性数字许可
- 计划扣款与实际扣款账本并存
- 免费试用、优惠期、涨价历史、失败扣款、取消与续费提醒
- 预计月/年支出与实际已发生支出分开
- 支持试用转正式、暂停/恢复、取消/续费和失败次数展示
- 价格变化、订阅标签、私有资料附件和关联提醒均保留历史
- 企业微信群机器人、Server酱和 PushPlus 均可作为通知渠道

不保存账号密码或 License Key；只允许保存普通账号标识和指向专业密码管理器的外部引用。

## 14. 数据安全与迁移

- 单管理员密码使用强密码哈希。
- API Key 和通知密钥可由环境变量提供，或使用应用主密钥加密后存入数据库。
- 便携导出默认排除所有密钥。
- 一键导出 ZIP：版本化 JSON、CSV、附件和校验清单。
- 导入前执行格式校验和冲突预览。
- 首版不提供批量 CSV 导入，也不适配其他资产 App。
- 首版不内置定时自动备份；只提供手工完整导出及 PostgreSQL/附件目录备份说明。
- 不做匿名遥测。版本检查默认关闭，可由用户显式启用。

## 15. 明确不在首版范围

- 多用户、家庭共享、多租户
- 消耗品、库存与日常记账
- PWA、离线模式、原生移动 App
- 发票 OCR
- 任何购物平台自动价格追踪或采集
- 自定义 Dashboard 编辑器
- 用户自定义指标公式
- 自动远端备份
- 账号密码或 License Key 保管
- 完整联系人系统
